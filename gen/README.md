# Generators

Scripts whose output ships: each writes patch specs into `data/specs/` from committed inputs (Olympus's firmware, the
`.s` sources here, the package). CI runs `gen/run.sh --check`, which fails when a committed spec is not what its
generator makes. A generator makes only the current version of its specs; a version that a build has been camera-tested with stays as a committed file under a new name for the next version.

The earlier versions `custom-menu-rows-5.json` and `light-box-row.json` (the camera-tested build light-box) are committed spec files; this script made them at an earlier commit and no longer does. `experiments/2026-11-19-light-box/NOTES.md` |

Run them all: `gen/run.sh`. It needs the MN103 binutils (`uv run epm2mod init`) and Olympus's firmware
(`uv run epm2mod fetch-stock`).

`data/specs/peaking-gain-2x.json` is one byte written by hand. Every other spec that no folder here writes was made by an experiment script; its notes in `experiments/` are the record.

Two generators (`interval/mkspec_v2.py`, `level-gauge/mkspec_step_b.py`) can also compare their work with the E-PL6
firmware: `uv run python gen/interval/mkspec_v2.py /path/to/OLY_E_112_1400_0000_0000.BIN.lzma`. The file is not in
the repository, no command fetches it and the generators look in no default place, so `gen/run.sh` never makes that
comparison: only the owner runs it, by hand.
