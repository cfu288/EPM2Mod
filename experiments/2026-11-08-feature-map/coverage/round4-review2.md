## CONTRADICTED items

1. **F023 / 0x7E707880–0x7E708311 is not the Exif/MakerNote writer.** Section 03 (scope line) and 14d §317 say "the Exif/MakerNote writer 0x7E707880–0x7E70B434". The 14d data table labels 0x7E84EE68– as "Exif/MakerNote/ORF IFD templates".
   - **Proof:** 0x7E707880 (`movbu (37,a0),d0; …; mov 0x7E84EE68,a1; mov (d0,a1),a1; calls (a1)`) dispatches over a 3-function table {0x7E70795C, 0x7E7079EA, 0x7E707A1B}. All three build an image-engine job and submit it with `img_exec` 0x7E544BB5.
   - **Callers:** `[MOV]imgdma_exec` 0x7E6DADB9, which names the modes `IMGDMA_ADD_YC/BAYER/RGB` for req+37 = 0/1/2; `REC MULTIEXP ADD EXEC` 0x7E7172B4; and art 0x7E71C7BE.
   - 13e already says that PrintIM/Exif starts at 0x7E708312, and section 12 puts the tag templates at 0x7E84EF20.
   - **Fix:** 0x7E707880–~0x7E707A9C = IMGDMA add (image add/merge job builders, used by movie, multi-exposure and art). The functions between it and 0x7E708311 (callers in the IMG library 0x7E550xxx) are not named yet. The Exif writer runs from 0x7E708312. The 14d row should start at 0x7E84EE74 or later.
2. **F029 / 15c class range "TraShareTakeStatus 0x7E967145–0x7E96C981" holds a second, unrelated singleton.**
   - **Proof:** 0x7E96C7F9 is slot 3 of vtable 0x7EBD0C4C. That vtable is stored by 0x7E96C670, which is called only from the ctor 0x7E9679DF of the singleton at RAM **0x602B0C88**, getInstance 0x7E967754.
   - TraShareTakeStatus is a different object: RAM 0x602B0C78, ctor 0x7E967145/0x7E967175, vtable 0x7EBCDBB4.
   - The method is a pure table lookup (0x7EBD0A84). It reads none of TraShareTakeStatus's state 0x602B0CB4–0x602B0D18.
   - The 15c builder's rule "end = next class start" gave the whole 21-KB span to one class.

## Side findings (not counted)

1. **DB mis-split at F029.** The entry for 0x7E96C7F9 (size 78) also holds the next virtual method, 0x7E96C822 (vtable slot 4, `retf` at 0x7E96C81F ends slot 3). Slot 4 has no direct caller, so the splitter never starts a function there. This is the same pattern as round 3's isTypeOf mis-split, here for vtable-only methods.
2. **An unmapped singleton at 0x602B0C88** (getInstance 0x7E967754, 14 callers; ctor 0x7E9679DF, which builds 7 sub-objects at +0…+24). Its +0 sub-object is the code-translation object above. Its eight methods 0x7E96C67A–0x7E96C92E use tables 0x7EBD0574/0x7EBD0824/0x7EBD09D4/0x7EBD0A84/0x7EBD0B54. Slot 2 (0x7E96C6D5) turns APP_EVENT codes (0x04020070, 0x04010001 external strobe, 0x02020000) into small numbers 33/34/… (V code; the role is I). It is not in any 13c/14c/15c table.
3. **PictBridge printer quirk (CapPbr).** 0x7EA59492 builds the supported-fileType mask this+564. When the printer's manufacturer string (this+3312) is `CANON` and its model (this+3224) is `CP-300` or `CP-200`, it sets a special flag that changes how the mask is built. When capability bit 4 of +3378 is clear, the mask is just 1 (V). The map has no printer-specific behaviour.
4. **A U_SHELL `face` family exists on the E-PM2.** It has 17 subcommands at 0x7E8DE4EC (`get`, `keep`, `reset`, `abort`, `prog`, `get_eye`, `dump`, `setting`, `log`, `load`, `set_pos`, `get_pos`, `set_info`, `mdm`, `reg`, `tune_l`, `tune_g`) (V). 13b cites a face debug command only from the E-P5. 15b lists the table only as "FACE_* 20 code pointers", and 10f does not list `face` among the U_SHELL families.
5. **`aud_dev_ctrl_io` 0x7E950594** (31 callers, 38 callees; `[aud_dev_ctrl_io] cmd=`) is the audio-IC command dispatcher (it covers line power, among others). Section 05 does not name this layer.

## Weakest areas (this batch)

- **The region between modules (FACE tail → mcon → Exif, ~0x7E6F5000–0x7E708311).** The FACE debug shell is unmapped, and the IMGDMA job module is mislabelled as Exif. modules.tsv has no row from `mov_sub.c` (0x7E6F43E2) up to `rec_3d.c` (0x7E70BDF4).
- **The class ranges in 15c-class-index.tsv are not reliable for membership.** The "next class start" rule puts helper singletons and code tables into the previous class (F029). Use the ctor/vtable columns, not the ranges.
- **Cap*/Cmp* classes have class-level labels only.** 7 of the 11 C++ functions here (F033–F039) get only "the class is right".
