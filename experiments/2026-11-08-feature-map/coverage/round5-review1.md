# Coverage review, round 5, batch 1 (20 functions)

Target: E-PM2 v1.6 block 0, database build/map (current). For each function I first wrote the map's prediction from docs/firmware-map.md (regions table), modules.tsv, tasks.tsv and sections 01–15d (including the 15a–15d TSV indexes; a script listed every map address within ±0x400–0x4000 of each function). Then I read the code with `fwmap.py fn/xref/range`, `disasm.py`, calls.tsv, strrefs.tsv and the ROM bytes. **V** = read in the code or bytes. **I** = inferred. No function in the batch has `suspect` = 1, and all 20 decode as normal code.

## CONTRADICTED items

None in the strict sense. Five map claims are imprecise or misleading; the proof is in the bytes:

1. **13f §2.3, "Per-channel mode hooks are in table 0x7E4C82F0"** (F002). 0x7E4C82F0 holds 3 **open** hooks indexed by the channel *mode*, not by the channel (0x7E467F4D–0x7E467F58: `asl2 d2; mov 0x7E4C82F0,a0; mov (d2,a0),a1; calls (a1)`). A second 3-entry **write** table follows at 0x7E4C82FC {0x7E46834D, 0x7E468424, 0x7E468578}. The dispatcher 0x7E468324 uses it with the mode byte from 0x60417508 + 8·ch + 1. A third table follows at 0x7E4C8308.
2. **15b-tsv, "0x7E667CAA trk lens input (0x7E52B2FE)"** (F015). 0x7E52B2FE is not a lens-state input. It is one half of the lens-distortion coordinate pair that the `bay2yc` / `yc2bay` test shell 0x7E52BC73 calls (0x7E52BBEC: flag ≠ 0 → 0x7E52B2FE, else 0x7E52B0F1). It is called with frame limits 319/239 (tracking) or 320/240 (shell).
3. **04 §(AVI), "audio format checks 0x7E6EADA3/0x7E6EAE7D (wFormatTag, nChannels, SamplesPerSec, BitsPerSample)"** (F020). Those fields are checked only by 0x7E6EAE7D (strings 0x7E80DECB–0x7E80E01F). 0x7E6EADA3 checks the strh fields fccType `auds`, fccHandler, dwScale = 4 and dwRate = 192000 (strings 0x7E80DDB5–0x7E80DE9E).
4. **15b §(lens request), "Alloc 0x7E533AB3"** next to a 24-byte request layout (F005). 0x7E533AB3(size) is a general two-pool allocator: ≤ 128 B from 32 blocks, ≤ 8192 B from 4 blocks (0x7E533AD2; pools built by F005). It is called with other sizes, e.g. 20 from `lens askdata` 0x7E525D56.
5. **02, "`askdata` (…; 0x7E525DDF)"** and **"shell `dcfnum/resetnum/eyefi` 0x7E5C5750"** (F004, F012). 0x7E525DDF is the askdata *usage printer*; the handler is 0x7E525D35. 0x7E5C5750 is the 44-command fallback of the `file` shell (called at 0x7E5C25CE), not a 3-command shell.

## Where the map is weakest

- **Function-level detail inside named libraries.** 16 of 20 are PARTLY. The map names the module but not the function: STL core (F001), SIO internals (F002), the lens memory pool (F005), FAT/DCF/DPOF internals (F009–F011), the CEC TX state machine (F019).
- **Callback and ops tables reached only through pointers** (F002, F008, F014).
