## Side findings (not counted)

1. **13c §1, `OlyHfwOpeLevel 0x7E9782AF–0x7E97858C`, ends one function early.** 0x7E9785D3 `Ope::startLevel` (F032) belongs to the same class. It is the counterpart of `Ope::endLevel` 0x7E9782F6, which is inside the range, and it uses the same TraShareTakeStatus helpers 0x7E9699B3/0x7E969E53/0x7E969A61. The cluster continues past 0x7E9786CF (small getters). Fix: end ≥ 0x7E9786CE (V for startLevel; the exact end is not checked).
2. **DB mis-split at F035.** build/map gives 0x7EA465CD size 40, which runs through the `retf` of the next function. `isTypeOf` 0x7EA465E7 has no direct caller and no prologue, so the splitter does not start a function there. 13c-event-ids.tsv already lists it correctly. This probably repeats for many event classes whose isTypeOf follows the ctor: the "ctor + isTypeOf" pair is ~1,268 times in the TSV (I, not counted).
3. **modules.tsv `play_apical.c` range 0x7E93BE70–0x7E93C39B understates the file.** By their own name strings, the `play_apical_*` functions run from 0x7E93BC2F (`play_apical_check_edit_enable`) to 0x7E93C68A (`play_apical_edit_make_exif_prm`). The column covers only the functions that print the file name. Readers will take first_fn/last_fn as file bounds (F030 falls inside only by luck).
4. **Links that are new to the map (V):**
   - Movie playback audio → AUD_MAIN: `abort_sound` sends command 70 synchronously to queue 0x7E43ECCC (F023).
   - HCI event dispatcher 0x7E924E3A with jump table 0x7EBB3C1C (index = event code − 1, codes 1–61).
   - HCI link-policy builders 0x7E9273A6–0x7E927576 (0x0801/0803/0804/0805/0806/080B) and the HCI command sender 0x7E925704(opcode, len).
   - `OlyHfwOpeLevel::startLevel` → `api_user_Start_Slope_Event` 0x7E68EC99 (level gauge, API side).

## Weakest areas

- **Blue SDK interior (0x7E91D279–0x7E937CDD):** labelled only "stack, identity inferred". The HCI command and event layers have a clear structure (opcodes, event jump table, link-record table 0x7DAC4C68 with stride 320), but the map has none of it (F028, F029; F027 is close).
- **String-less driver internals in 0x7E6A–0x7E6B:** the HDMI-DRV EDID state and the display-controller (0x9A900000) register helpers are mapped only as "task + strings" (F021, F022).
- **C++ app layer at method level:** the 13c/13d/14c signatures classify every C++ function in this batch correctly (ctor, handler, API method). They do not say what a given Cmp/Cap/SequenceParts method does (F034, F037–F040). Info ids such as 4011 have no meaning attached, and CapImg interface stubs are not marked.
- **Movie recorder/supply helpers:** the map stops at task level, so helpers such as F025 have no role.
