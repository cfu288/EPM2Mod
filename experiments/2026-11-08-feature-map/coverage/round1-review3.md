## Map claims that the code contradicts (claims these functions touch)

**C1. Event-class count and location (section 06 §1).**
- The map says: "930 data words point to 0x7E966B30, so there are about 930 event classes"; "most event vtables are in 0x7EBCE000–0x7EBF0000"; "the event constructors are in 0x7E96B000–0x7E9823AB".
- **The code shows otherwise:**
  - A scan of block 0 for the event-vtable pair {slot 3 = 0x7E966B30 getId, slot 4 = 0x7E966B37} finds **1,273** vtables.
  - Only **574 (45%)** of those are in 0x7EBCE000–0x7EBF0000. 342 are at 0x7EC4xxxx and 129 at 0x7EC8xxxx (`getid.py`). Even fwmap's `ptrs.tsv` has 1,184 words pointing to 0x7E966B30, not 930.
  - The ctor signature is `mov vt,d0; mov d0,(a0); mov id,d0; movhu d0,(4,a0)`. It occurs 1,037 times; **664 are outside** 0x7E96B000–0x7E9823AB.
  - Of the 593 direct calls to the base event ctor 0x7EBA48BC, **559 are outside** that range.
- Examples from this batch:
  - event 27503: ctor 0x7EA84980, vtable 0x7EC4D57C (F047);
  - event 12067: ctor 0x7E9EAD9D, vtable 0x7EC1F6AC (F056).
- Rhapsody puts each event's ctor in the module that declares it, not in TraShareTakeStatus.

**C2. "0x7EBA6B03–0x7EBE1020 = strings and rodata" (section 05, region table, marked verified).**
- Code continues past 0x7EBA6B03 to about 0x7EBA9xxx. Examples:
  - `getCurrentEvent` 0x7EBA6D64, called by F045/F054/F057 and 12,693 call sites in all;
  - the OXF event loop 0x7EBA74BB, which section 06 itself verifies;
  - `mainThread` 0x7EBA792C.
- The regions table in `firmware-map.md` ("OXF runtime … then vtables") has no exact boundary, so it is not contradicted. Section 05's boundary is.

**C3. Stale "no accessory port" status (sections 05 and 06).**
- Section 06 §2 says: "The E-PM2 has no accessory port, so this is probably dormant". Section 05 says: "Probably dormant on the E-PM2: this body has no accessory port".
- `firmware-map.md` §3/§5 has already retracted this claim (VF-4 support in v1.2).
- These are internal contradictions of the map, not code findings. They apply to F045 (`CapBlu_Bluetooth`) and to the DevBlu neighbour of F060.

## Where the map is weakest (from this batch)

1. **Whole C++ classes are missing from the map.**
   - `CapPls_PlayState` (≈0x7EA27D00–0x7EA2FC00): the playback-state capability, with calendar paging, play info, image overlay and MPO search.
   - `CapBlu_Bluetooth` (≈0x7EA4E600–0x7EA52500).
   - `Cmp_PictBridgeComponent` / `CmpPbr` (≈0x7EAEB000–0x7EB02000, ~90 KB).
   - The OSD sub-machine of `CmpCst_Function` (0x7EAA0A1B–0x7EAA2400).
   - The unnamed USB-comm device class beside DevBlu (vtable ≈0x7EC916F0).
2. **The Com_ framework at 0x7EB855C7–0x7EB89xxx is missing.** It holds the observer subject (addObserver / notify-all), GEN-to-self, event resend, `handleNotConsumed`, the `*** on state ***` trace and the CmpInit helper. Nearly every component calls these functions; for example, F046, F047, F050, F058, F059 and F060 all depend on them. The map names only the transition manager at 0x7EB8A000.
3. **modules.tsv `first_fn` is "the first function that names the file", not the start of the file.**
   - Code before it is left unplaced: F046 is before CmpShc, and the `CmpCst_Function` class string is 30 KB before its first_fn.
   - Large gaps between files have no owner: 0x7EA27–0x7EA32, 0x7EA48–0x7EA65, 0x7EAEA–0x7EB02, 0x7EB7F–0x7EB8A.
4. **There is no event dictionary.** Ids 12067 (play "done → Idle", tested ~1,170 times), 27503, 11562/11563 (init ok/err) and 11769/11566/11761 cannot be named from the map. Open question 4 of section 06 is still the main gap, and its count is wrong (C1).
5. **Statechart glue is not modelled.** The map describes Rhapsody naming, but not the state-variable layout (+208/+212 root, per-region slots), `popNullConfig` 0x7EBA6695, `getCurrentEvent` 0x7EBA6D64, or the inlined per-component handler templates (F053/F054/F057 are byte-identical apart from offsets). With that layout, most of these 63–400-byte functions would be EXPLAINED by pattern.
6. **The API trace ring is not in the map.** It sits at RAM 0x602B0E9C (entries `{0xE1000000|apiId, arg, 0xDEADBEEF}`, exit hook stubbed to `retf`), and every OlyApi entry uses it (F041).
7. **Minor gaps.** The regions table row for 0x7E4E–0x7E52 does not list the soft-float/double helpers at 0x7E5010EA–0x7E5019ED (2,260 callers for the single-precision multiply 0x7E5018E8); only section 08 mentions them. That multiply uses `udf01`/`udf04` on mantissas, which is consistent with the `udfu01` = multiply inference.
