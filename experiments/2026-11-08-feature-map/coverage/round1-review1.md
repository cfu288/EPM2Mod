## CONTRADICTED items

None. No map statement is proven false by these 20 functions. Two near-misses:
- **FSN objects (F014):** the map lists FSN1 only; the code creates FSN1, FSN2 and FSN3. The list is incomplete, not wrong.
- **"PSP names the background layer" (10c §3, inferred):** the PSP source file also renders all four windows, with per-window WB set-up and `img_exec` (F019). This weakens the reading that "PSP" means only the background. The verified part of 10c ("background types plus a per-window layout") holds.

## Where the map is weakest (from this batch)

1. **Libraries without strings are missing.** Two whole blocks have no entry in the map, and the regions table describes their ranges with unrelated modules:
   - the C runtime 0x7E4F8000–0x7E501C5B (strtok, F003);
   - the IMG / colour-curve library 0x7E54D000–0x7E578000 (F005, F006), shared by REC_IMAGE and MOV_COLOR, with mode tables at 0x7E789600.
   The regions-table row 0x7E521020–0x7E621020 does not mention image processing.
2. **Driver internals.** These drivers appear only as shell entries or task names:
   - SIO (F002);
   - the jog-dial counter hardware at 0x9A600000 (F004);
   - the 0x99900000 shutter(?) unit (F015);
   - the FAT layer (F008).
   No MMIO block is named.
3. **State machines and handler tables.** The TAKE release-ready sequencer (state table 0x7E7908C0, 15+ named states) is not in the map (F007). The same applies to the strobe light-source selection (F011) and the strobe exposure calculation (F010).
4. **Function-level detail inside known modules.** The module is usually right (13 PARTLY verdicts), but the map stops at task or file level. F012, F016, F019 and F020 are EXPLAINED only because their names or strings were quoted in a section.
5. **Tool error: callback entry points are missed.** Functions whose address is loaded only with `mov imm32` (IRQ handlers, callbacks) get no start, so they merge into the function before them:
   - F011 contains 4 callbacks;
   - 0x7E509491 contains the jog callback 0x7E5094B6;
   - 0x7E6554F8 contains the IRQ handler 0x7E655548.
   The function count and the caller statistics are therefore wrong near drivers.
6. **Module boundaries.** modules.tsv gives only the first function that names a file, so ownership between named files is guesswork. Examples: F014 (cam_frame.c or cam_frame_sync.c), F015 (inside the cam_set.c span but shutter-related), F018 (in the mov_art.c/MOV_BRIDGE span but AVI-index code).
7. **Minor.** `udf00 imm,reg` also behaves as a multiply (F013: `udf00 150` then `/100`), so open question 7 should cover udf00 as well as udfu01.
