## CONTRADICTED items

No function verdict is CONTRADICTED. One map claim that these functions depend on is contradicted:

- **Event 3344 "capability init error (relayed)"** (15c-event-id-fixes.tsv; 14c §2.2 "+424 → 3344 init error"). Sub-transitions send 3344 to their owner (+160) **on every evTraStop**, not on an error:
  - F059 0x7EB7F2CA: isTypeOf(11769) → clear list → `new` 3344 (ctor 0x7E9EB15F) → GEN to (160,this), with no condition.
  - RecViewController 0x7EA77085 does the same and logs `evTraStop recieved! RecViewController is not standby` only afterwards, when state ≠ 6.
  - In the Com_ init chart, 11563 does notify list +168 (the 3344 path) and 11769 notifies +188. So 3344 has at least two uses: an init-error relay, and the sub-transition reply to "stopped".

  The single name "init error" is false for the Com_ManagersSubTransition senders. The fixes TSV itself lists those senders (RecViewController ×3, "Com_ManagersSubTransition subclasses (record) ×2").

## Weakest areas

1. **No per-function index for the app layer.** 15c gives class ranges and shapes, which is enough for the generated boilerplate: getName, slot-33 dispatchers, go-to-Idle handlers and the boot step. It says nothing about which state a function enters or which request it serves. 11 of the 20 are PARTLY for this reason. State numbers and names (EBea 81 `end_adjust_animation_start`, EPro 51 `start_protect_start`, CapPxm 7, MultiThrough 3) can be read from the bytes and the log strings, but the map does not record them.
2. **Event-id dictionary gaps.**
   - 16153 is `evTraCmpSts_Start3dOverlap` (V by its test site) but has no name.
   - 7006 has no name. It is a "register an observer" request.
   - 14381 has no name, its owner is still "OlyHfwPower" in 13c-event-ids.tsv, and no consumer was found. It is CM's recursive `dumpState` event.
   - 3344 has an over-narrow name.
3. **Vtable slot semantics beyond the OXF/Com_ core.**
   - Com_ slot 35 is unnamed. It is `dumpState(level)` (F046).
   - CapPls iface slot 145 is not listed (F042: playback zoom-out/index step).
   - The CmpSqp vtable (slot 2 = the flag op on 0x602B35CC; slot 240 = the stop-exposure guard) is not described.
   - The Dev slot tables (DevBlu slot 3; the pixel-mapping Dev slot 3 → `api_rec_Calculate_Pixelmaping`) are not described.
4. **Playback view state.** The play-info block 0x605E5380 is described only as "accessors". The map does not record the zoom table (×1.0–×10.0 in 11 steps), the index sizes 4/9/16/25 or the view-mode byte 0x605E53E4. 14c §2.6 lists these fields as an open question.
5. **Feature chains not joined.** The pixel-mapping chain is in the map in pieces: 10f, the 13c Dev table, the 15c 6061 owner. The CapPxm state-7 hop (F043) that links them is missing.
6. **modules.tsv is still unreliable as a file map in this area.** 9 of the 20 functions fall in gaps or outside the first_fn..last_fn of their own file. Examples: CCom first_fn 0x7EAB2756 > F048; SOve first_fn 0x7EB751B9 > F057; PSld first_fn 0x7EB681FE is a parent state handler. Only the class index places them.
7. **Region-local state words.** PPnr's Idle lives in +6608/+6612 (F054), not +212. The "+212 = rootState_active in Cmp components" rule has unlisted exceptions.
