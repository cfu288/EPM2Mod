## CONTRADICTED items

None at function level. Each function's subsystem and module are right in the map.

There is one contradiction at map level, found with F012 and F013. The **regions table and 15b §(D4 note)** say that the row 0x7E6211E1–0x7E6A935C begins with "Camera core (`cam*.c`)" and that "0x7E6211E1 is the first camera-core function". Section 03 (fcs/AF helpers 0x7E6211E1–0x7E627E9E; cam.c starts 0x7E627E9F) and 16d (component "fcs/AF code tail") say otherwise, and so does the code:
- 0x7E6212B5 logs `fcs_sub_iaf_set_lens_pos_info`;
- F013 0x7E626BE3 is called only by the AF/FCS init 0x7E5E2988 and sets up the AF trace globals 0x6054C79C–0x6054C7B4;
- F012 0x7E625123 is called only by the IAF per-frame evaluation 0x7E614C8F.

The AF/FCS region therefore ends at 0x7E627E9E, not at 0x7E6211E0. The first 27 KB of the "camera core" row are AF code.

A smaller error: 14b §4 says that frame-command starts launch the request "through the object's vtable +32". The start 0x7E637232 calls `(60,a2)`, a field of the object (F014).

## Weakest areas

1. **Lens module interior (0x7E51BF67–0x7E538C1D):** F003, F004 and F005 have only call-graph rows. The map has the request layout (15b §5.2) but names none of the poll requests (class 5 modes 0x10/0x11, flag 0x6050265C, timer 0x60502660), the `.data` fallback lens blocks, or the lens-supplied AF correction polynomial (rec+5444, 36-B sets, flag +8891).
2. **fcs/AF tail 0x7E6211E1–0x7E627E9E:** the regions table labels it camera core (see above), and its 16d rows are mostly "helper called by X" or "hardware loop". F012's area-state gate and F013's trace init have no role in the map.
3. **BC sync API codes:** 15b lists code 31 as handled and lists TAKE callers, but gives no meaning for codes 20/31 or for why the result goes to the AF-side store 0x6054C458 (F007).
4. **IMG op types:** table 0x7E74A3C8 is called "geometry", but no op number has a name. Op 10's handler (F006) and the coefficient builder 0x7E550766 (three rows of {c1, c2, c3, 1.0 Q20} plus Q16 gains) are not described.
5. **BML/STL internals:** the 15d split is good, but the functions under 0x7E42380A (map scan / mount) are all "helper of …, under STL format". F001's wrap-around age compare is not mentioned.
6. **Rule-generated "features" rows in 16d** (basis `features+call graph`, marked V) were the least reliable: F013's row is wrong, and F012's row is empty context.
