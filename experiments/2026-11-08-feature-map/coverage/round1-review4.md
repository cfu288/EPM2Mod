## CONTRADICTED items, with proof

**F076 (0x7F066AD5): the map says it is the DPS XML library. The code shows a face-detection helper library.**
- Map claims:
  - §08 table, DPS_MAIN row: "DPS XML library at 0x7F061020–0x7F068F9C";
  - regions table: 0x7F05C000–0x7F06B000 = "BASIC interpreter and DPS (PictBridge)".
- The only entry into 0x7F0645C1–0x7F069000 from outside that range is one call, at 0x7E6FC062 in 0x7E6FBFB4. That is face code: it loops over at most 8 faces, uses 22-byte face records, and sits next to `OKAO_*` (0x7E6FBCB0) and `FACE_EXEC` (0x7E6FC27E). §03 itself says that FACE_MAIN cmd 5 → 0x7E6FBF38, and 0x7E6FBF38 → 0x7E6FBFB4 (verified in calls.tsv).
- 0x7F0645C1–0x7F069000 (about 18 KB) references **no strings at all** (strrefs.tsv). The DPS code (0x7F05F840–0x7F062E4B, strings `HREQUEST.DPS`, `xmlns`, `paperSize`) calls only up to 0x7F064567.
- Outside calls from the range: memcpy/memset 0x7E500D33/0x7E500D73, alloc/free 0x7E72D0BA/0x7E72D169 (these are also used by art-filter code 0x7E72E3EE, 0x7E7314D4), and maths helpers 0x7F069020–0x7F069171. None of them is DPS.
- Cross-check: §09b open question 1 found that 0x7F0687C4 writes the art composite descriptor +284. 0x7F0687C4 is called only by 0x7F0646A0, which is in this same face-driven subtree.
- **Correction:** the DPS XML code is about 0x7F05F840–0x7F0645xx. 0x7F0645C1–~0x7F069000 is a face-triggered image-analysis library, also in overlay A.
- **Implication (inferred):** FACE_MAIN cmd 5 needs overlay A to be loaded. Section 01 says overlay A loads only through Usr2 bit 0.

## Other map problems found on the way (not verdicts in this batch)

- **§08 says "The BASIC-like interpreter (BAS_MAIN, …) at 0x7F021020".** §01 and the regions table put BAS_MAIN at 0x7F05C000 (overlay A). 0x7F02FF00–0x7F030200 holds the AVPI strings and vtables (`Audio Source Plug-in`, `CAvpiAsoAudioSource.cpp` at 0x7F02FF0D; the vtables of F073/F074). The regions table has **no row for 0x7F021020–0x7F034000**. The map does not cover this area, and §08 labels it wrongly.
- **AVPI starts before 0x7EEA.** The callers of F071/F072 show that AVPI framework code (OS layer, format objects) is at about 0x7EE8F–0x7EEA0. The only callers into 0x7EE80000–0x7EEA0000 from outside the library region are three C3D-scene calls to 0x7EE80024/53/9C. The rest is called by AVPI. §08 leaves 0x7EE63–0x7EEA unassigned.
- **Overlays A and B depend on each other.** Overlay A (F075, DPS) calls `strlen` 0x7F087BD1 in overlay B (verified: 69 call sites in 28 functions, all in 0x7F05EC0D–0x7F064584, e.g. 0x7F060DCD). §01 describes Usr2 bits 0/1 as independent loads.
- **The DB merged FormatStore and GetDevicePropDesc.** DB function 0x7F0940EC (494 bytes) runs up to 0x7F0942DA, so it contains GetDevicePropDesc 0x7F0941D2. That is why "FormatStore" appears to call the property switch 0x7F08D380.

## Tool errors (function splitting)

- F063, F064 and F073 each contain a separate one- or two-instruction virtual method at their tail: 0x7ED1CA54 (word 0x7EF1096C), 0x7ED2D66A (word 0x7EF14570) and 0x7EEA276A (word 0x7F030168). The `ptr` start rule accepts only `movm` prologues, `retf`/`ret` stubs and `add -N,sp`. Getters such as `add 196,a0; retf` or `mov (160,a0),d0 …` are therefore missed, and their bytes are added to the previous function. The aligned vtable words point at them, so they could be added as starts when the target is inside another function's span.

## Weakest areas of the map (from this batch)

1. **The GUI C++ layer 0x7ECA–0x7EE2 below the menu tables:** 5 of 9 GUI functions are UNEXPLAINED. The map has nothing on the widget toolkit (vtables 0x7EF1xxxx, factory 0x7ED17DB8), the panel classes (`GCPnl_*`), the GUI object-type registry (0x7EFC5470), the generated `Ss*` state/handler tables (0x7EFD2400, 0x7EFD8CDC), or the PictBridge print GUI.
2. **0x7EE63–0x7EEA and 0x7F021020–0x7F034000:** both are AVPI (code, and rodata/vtables). Neither is in the §08 library table or the regions table.
3. **Overlay A layout:** the DPS range is wrong (it starts lower and ends near 0x7F0645xx). About 18 KB of face-driven code is labelled DPS.
4. **Function-level roles in the connectivity stack:** the module names are right (PTP, ADJ, PC_HOSTCOM). But per-property and per-sub-command meanings are missing, for example the ADJ 0x9029 remote key injection and the PTP FlashMode encoding.
