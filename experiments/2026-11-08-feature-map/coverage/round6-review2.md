## Side findings (not counted)

1. **16a 0x7EA1D604 "CapThr_ThroughImage returns 0" is wrong.** The bytes are `clr d0; call 0x7EA1CA98; ret`, so it is a wrapper: `Restart_Through(this, 0)`. The `getter-setter` rule read `clr d0` as a constant return. It has 4 callers, including F033 (V).
2. **16a 0x7EA18D55 "transition action on 11566"** is a 2-instruction getter `mov (0x602B2E54),d0; retf` of the CapThr entry state, with 85 callers. A role of "transition action" does not describe it (V). F033 calls it and discards the result.
3. **16a 0x7E9E4C43 class "OlyHfwOpeSndCtl"** is a range artefact. The function calls `api_user_Set_Touch_Panel_State(0)`, and its only caller is OlyApi `TouchPanel::endTouchPanel` (F029). The 15c "SndCtl" range 0x7E9E3445–0x7E9E600C holds string-less touch-panel Ope code after the SoundEvFw methods (about 0x7E9E4B3D onward). The forwarder target 0x7E9E4D65 (11 callers) belongs to the same object (I: an OlyHfwOpe touch-panel class).
4. **05 §3.6 "selects I2C channel 2 (0x7E6BAF45)"** is imprecise. SIO channel 2 is taken by F021 through `sio_request(2, …)`. 0x7E6BAF45(n) only drives port line 224 to n through 0x7E461469: a mux/select line. 13f uses the same helper (arg 1) for its ch3 device-0x72 path, so the line is not specific to ch2 (V).
5. **05 §2.1 `mono_stereo`:** the DAC path function also takes `mono_stereo`, but it ignores it (log only) (F025, V).
6. **OBEX task message protocol (05 §4 gap):** the message types are 1 → 0x7E93B06C, 2 → open (0x7E93B1C8; sets 0x605D6DF0 = 1 and allocates 0x605D6DF8), 3 → 0x7E93B214, 4–7 → callback slots +4/+8/+12/+16 of the per-state table at RAM 0x602B4BB0 (F022, V). Who fills that table was not found by a direct address search (it is written through a base pointer).

## Weakest areas

- **Per-method roles inside named C++ classes** (CapImg F031/F032, CapThr F033, CapPCM F034, CmpSqp F036/F037): the class is always right, but the 16a rows for string-less methods are call-graph context only. The internal ids (CapThr entry-state constants such as 0x02010001, CapImg play-buffer slot ring, Event-View animation) are not in the map.
- **OBEX task internals** (F022): the map has the task and its state names, but not its message types or the per-state callback table.
- **Mislabels created by class ranges in 16a**: a string-less sub-object inside a class range takes the range's class (touch-panel Ope inside SndCtl, side finding 3). A `clr d0; call` wrapper is read as "returns 0" (side finding 1).
- **Strong areas in this batch:** OlyApi methods (F027–F029; the API-id rule is exact), Rhapsody handlers and entry actions (F038–F040; state numbers and events verified against the jump table), and playback edit-mode functions (F023/F024) all matched the bytes.
