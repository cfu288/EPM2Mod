# Coverage review, round 4, batch 4 (F061–F080)

Method: for each function, I first wrote a prediction from the map only. The sources were the regions table in `docs/firmware-map.md`, `modules.tsv`, sections 01, 07-settings.tsv, 10d, 10f, 11, 13b, 13d, 13f, 14a, 15a (md and tsv) and 15d. Then I read the disassembly, strings, callers, callees, vtables and data tables (`tools/fwmap.py`, `tools/disasm.py`, raw reads of block 0). I used the D1 Ss handler table (`scratchpad/d1/gui-toolkit/ss/handlers.tsv`, `events.tsv`), the D3 key map (`scratchpad/d3/gui/keys.txt`) and the English block-1 strings (`out/lang/101_1600.en.tsv`) only to name handler rows, event ids, key codes and string ids. OlyApi method names come from the `Class::method` name strings: method id `0xGGCCMM` = the MM-th name of the class. I checked this order against the log strings in 0x7ED0A91B (canProtect = 03.01.0C, changeProtect = 03.01.0B). Scratch: `/tmp/scratch/04b1caa0-6975-4677-98e3-f42129671871/scratchpad/coverage4/batch4/` (per-function `fwmap fn --dis` dumps and `rd.py`, a raw block-0 reader).

"verified" = read in the code or bytes. "inferred" = from names, strings, standards or layout.

## CONTRADICTED items

All 14 callers are SS_USB handlers (0x7EDC0D90–0x7EDC156F, the SS_USB handler code range of 13d §4.2).
- Fix: GuiTouch ends at 0x7EDE15ED. 0x7EDE15EE–0x7EDE1D09 is the USB-connect screen class (getInstance, ctor, show 0x7EDE1649, …). That class is created by SS_USB, not by openPage. 15a's "page class 0x7EDE1649 base (derives from 0x7EDCCA5D)" row should name it.

## Where the map is weakest

- **Overlay B after the C3D bridges (ADJSLF, file wrappers 0x7F0864xx–0x7F0867xx).** The map has one paragraph (01 §7) and a range that is too short. The record/CSV writer, the file-open layer and the per-unit sequences (`UnitCodeCam/Body`) are not mapped (F079, F080; the `adj_p15740_p.c` property handlers of F078).
- **AVPI framework classes 0x7EE90235–0x7EE9C331.** The map still says "individual class roles are not mapped". The graph object (clock swap, element list, state +164), the pins and the plug-in base methods can be read only from the code (F074, F075).
- **Ss handler and page-method level of the GUI.** The SS ranges and page rows are correct, but no individual handler role is mapped. Most of the useful naming came from the D1/D3 scratch tables (handlers.tsv, events.tsv, keys.txt), which are not part of the map (F061, F063–F065, F067–F069). Examples: Fn2 = Protect in playback, a mode-dial turn cancels a BT receive wait, Edit › Aspect save with the Busy/warning paths.
- **Object boundaries next to range ends.** F066 (GuiTouch end) and F069 (page-351 end) both sit on a boundary that the map draws one function too late or too early.
- **C3D framework property setters.** The class tree is good enough to name ctor levels (F073 EXPLAINED), but the setter fan-out under 0x7EE7CE22 (F072) has no field names.
