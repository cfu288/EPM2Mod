## CONTRADICTED items

No function in the batch is CONTRADICTED in its main role. Two side claims in the rows I checked are false:

1. **13f §2.4, about F008:** "The U_SHELL `file` entry 0x7E5C2139 is the stub just before it." The bytes at 0x7E5C2139 are `cf a0` (`movm [d2,a2],(sp)`) and `f8 fe f4` (`add -12,sp`), and they fall straight into 0x7E5C213E. So 0x7E5C2139 is F008's own `calls` entry (prologue), not a separate stub. The data words 0x7E732738 / 0x7E733348 / 0x7EBCC350 point there. The direct callers (0x7F09D95D, 0x7F09D9F4) use `call 0x7E5C213E,[d2,a2],20`, which does the same movm and frame. This is the two-entry rule of 14e; 13f should call it the indirect entry of the same function.
2. **04 §(tasks) MOV_BRIDGE row: "cfg 0x8088".** USRSTART_THIRD starts MOV_BRIDGE with `movhu (0x7E43E94C),d0` → `call 0x7E449541` at 0x7E5051BD, and the u16 at 0x7E43E94C is 0x8087. The task record has the id **before** the entry: {0x8087, 0, 0, 0x7E6CE4AC, pri 4, 0x400, stack 0x604DF780}. The same layout gives DBG_OUT {0x8085, …, 0x7E5065EF}. 0x8088 belongs to the next record. tasks.tsv and 01 (0x8087) are right. 04 states that it assumed the layout {entry, pri, size, stack, id}, and that assumption gives every id one record too late. The "IMG0_LOCAL (cfg 0x8E)" line in the same table may have the same off-by-one (not checked).

## Where the map is weakest (this batch)

1. **MEC layer below the command handlers (0x7E518E91–0x7E51BA08, 0x7E51BA35–0x7E51BE9E).** The map has only the generic pattern "MEC sequence steps". These are not described:
   - the 12-entry operation table at RAM 0x604F63FC (filled by 0x7E518FBD), with its two variants chosen by 0x604F639C (slot 4 vs. slot 10 for MAG STOP);
   - the 9-entry core vector tables (0x7E513B81 at 0x604F642C, 0x604F64E8 and 0x604F5FDC);
   - the mec_timer.c API (0x7E51BA35 / 0x7E51BAC5 / 0x7E51BB59; timer ids 11, 12, 16–18);
   - the mec_ev event ids (e.g. event 33 = which of two delays ran out first).
   F001 and F002 are both here.
2. **Step and callback functions of event-driven sequencers.** Still sequence steps in cam_still_func.c (F012: cam_ev object 27), the strobe red-eye pre-flash train (F009: N = prm 0xD4D2 pulses at 33 ms, 0.9 s in total) and the AF peak/scan helpers (F010). The map names the dispatcher or the event object, but the sequences themselves are not traced.
3. **Lens status bits.** Word 0x604F6580 bit 28 (latched in 0x604F8F50, used by FCS and SDET as "AF not available") and bit 29 (CAMON/CAMOFF_AF_STOP) are not documented (F003).
