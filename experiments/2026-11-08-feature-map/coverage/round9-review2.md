## CONTRADICTED items

None. The map makes no confident false claim about these 20 functions. Two smaller inaccuracies in the text near them:
- 05 line 133 says the `ecor` **and** `IKEY` strings are compared with the Olympus company names. In fact only `ecor` is. IKEY must equal `PRM_AUD_BGM_VOL` (F025, V).
- The 16d row of 0x7E6FCDB7 says "probably: shell `camera_set <modedial>`". The function is the API **`mcon_if_camera_set`**: 5 app-layer callers log that name (changeModeConflict, start/endLiveGuide, startShootingService, setMyMode), and the shell is only one of its 6 callers. The row is hedged, so this counts only as far as it is hedged.

## Side findings

1. **Index gap 0x7E965FD1–0x7E966A16 (18 functions, V).** 16d's playback/audio/BT range stops at 0x7E965FD0 and 16a starts at 0x7E966A17. No 16x TSV has a row for these 18 functions (F026 is one). Only 13c §1 covers them, at region level ("user-shell support code, ANSI `ESC[`"). From F026: they include the U_SHELL `[Command Window]` terminal helpers (DECSTBM 0x7E966113, and probably the clear/home helpers 0x7E9660D9/0x7E9660F1, I).
2. **OXF container templates are not in the map (V for F040's class).** The OMQueue-like class (vt 0x7EC4810C, ctor 0x7EA6C5E5, slots 0x7EA6C622…0x7EA6C7D3) sits inside the "Cap_PlaySlide + CmpShc" range, but the OXF runtime (0x7EBA582D) and CmpSts_RecordController use it. 13c has no entry for container templates. So the 16a range-based class labels for this vtable's methods (0x7EA6C622, 0x7EA6C633, 0x7EA6C66F, 0x7EA6C70B, 0x7EA6C81D, 0x7EA6C992) are misleading. Other template instances emitted elsewhere would get the same labels (I).
3. **F025 refinement for 05/10d:** BGM authentication returns 2 only when `ecor` ∈ {`OLYMPUS CORPORATION    `, `OLYMPUS IMAGING CORP.  `} **and** IKEY = `PRM_AUD_BGM_VOL`. Return value 0 ("NG") is never produced by this function; it must come from its caller 0x7E960B7B (I).
4. **0x7E6FCDB7 should be named `mcon_if_camera_set`** (the 16d row and the "busy-guarded wrappers" component). The behaviour in the row (busy check, dial lookup 0x7E6FCCF3(dial, 2), camera_set 0x7E700D13) is right (V).
5. **ART history ring (F022 context):** a 100-entry u32 ring at 0x605BFAB8 with its index at 0x602AE424, printed by `art dbgall` → 0x7E71D18A. Each record is {u8 key, u8, u16} and is decoded through the {u8 key, fn} table 0x602AE428 (V). The map lists `dbgall` only as a subcommand.

## Where the map is weakest (this batch)

- **CapImg_ImagePlayer field accessors and lifecycle methods (F031, F033, F034).** The class is right, but the rows are only "calls the HLS logger, vt slot N". The fields +616, +618 and +736, the 4-slot play-buffer table at +1040, and the BT-communication guard +426 are not described. Most of these methods log only `F[CapImg_ImagePlayer.cpp] L[n]`, so the own-name rule has nothing to use.
- **Small app-layer leaves (F035, F037, F030).** The rows list the mechanics correctly but leave out the behaviour: the rec-view rectangle in CapBea, the mode-7 guard and buffer flip in CapRev's Stop action, and the mcon apply step of changeMode.
- **Framework code placed inside app class ranges (F040).** Range-based class labels fail for OXF template instances.
- **The 16d/16a seam (F026).** 18 functions have no per-function row.
- **Protocol helpers below the handler level (F024).** SDP server handlers are named, but the per-record UUID match is only context.
- **Strong areas:** mcon hedged rows (F021), micro-summaries (F022), the 14d false-function list (F023), named audio functions (F025), the event-ctor, OlyApi-method, own-name, dtor, state-entry and initRelations rules (F027–F029, F032, F036, F038, F039). These were all right, including the 4 hedged I rows.
