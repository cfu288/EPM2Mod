## Weakest areas

1. **GUI panel private methods (16b `synth`/`range` rows, I).** Panel 42 (type 0x6020) has no ShowPanelEx site and no purpose in the map. Panel 56's rows list setters only. F060 is a recognisable feature (the `%03d-%04d` folder–file number in the DPOF menu), but its row says just "setVisible". It misses the swprintf-like helper 0x7ED37429 and the label setText body 0x7ED28AB1. The 16b callee summariser seems to count only the named widget setters. A rule that reads format strings and direct widget-vt bodies would help.
2. **CA row handlers marked "not fully analysed".** F057 looks like a simple Boot step (0x1003 → 0x1004). In fact it re-runs `startServiceBootSubAppStateBoot` and issues `setSubAppChgReqInfo`, so it chooses the start-up sub-app. Rows in that state hide the main side effect.
3. **Ctg categories have numbers, not names.** "Switcher 2" (0x7EB96B3C–0x7EB9BCC2) is the playback component switcher (`ChangeCompoPlay*` strings, Cmp_PlayComArchitecture). The map does not say so. The 7001–7020 evTraCom ids that it sends (7002) also have no names.
4. **State meanings outside the Cmp_PlayComponentBase work states.** The handlers of CmpCst_Function (13→35, 61→79) and PictBridge (145, 155/156, the composite +1332 with sub-states 87–109) are mechanically right. The map has no state-name table for them, so "what state 61 is" has to come from neighbouring strings (here: stop the through image).
5. **Tool gap (fwmap data xrefs).** `fwmap fn 0x7ECDF83A` reports 3 data words, but the raw binary has 5 (it misses Misc 0x7EED9368 and Pc 0x7EEDA40C). The 16b row has them because it reads the tables directly. A reviewer who relies on fwmap's xref list will undercount table uses.
6. **modules.tsv coverage in the app layer.** 10 of the 15 app functions (F042, F045–F048, F051–F055) are outside every `.cpp` range (classes without a `.cpp` string, or code after the string run). Only the 15c class ranges place them.
