## Side findings (not counted)

1. **BTTIM row (05 §3) is wrong about 0x7E9014C6.** The row says "health check 0x7E9014C6 every 100 ticks". But 0x7E9014C6 is `mov (0x605C8850),d0; retf`, a 2-instruction getter of the BT_CTRL timer's remaining time. BTTIM calls it on **every** tick (0x7E92F3A4). Only when it is ≠ 0 does BTTIM count to 100 and call **F026 0x7E9013BC**, the countdown that sets BT_CTRL flag 0x10 (`bt_ctrl_timer_timeout`) (V, 0x7E92F3A4–0x7E92F3BE).
2. **0x7E707A9D–0x7E708311 ("unnamed IMG-library helpers") holds a TIFF/IFD tag reader (I).** 0x7E707E1A takes {IFD index ≤ 14, tag} and walks a parsed-IFD context (error codes 0x7326–0x7328; special handling of IFD kinds 6–13). Every ORF tag check in `play_load_raw` (0x7E941493–0x7E9416B6) calls it and 0x7E7080F1. Other callers are 0x7E550E9C/0x7E551081 and 0x7F08C103/0x7F094CC9. This fits an Exif **reader** placed next to the Exif writer 0x7E708312, not generic IMG code.
3. **Effect type → EFFECT_EXE bit** (answers part of 05 open question 9; V from EFFECT start 0x7E8F6E64 and its callees): type 6 → 0x40, 10 → 0x10, 11 → 0x08, 27 → 0x20, 28 → 0x80 (+ bset 32), 29 → 0x100 (+ bset 1), 30 → 0x200 (+ bset 4 and 16). The `effect` shell uses `index` = 6, `slide` = 11, `overlap` = 27, `tpsl` = 29, `tpsc` = 30, and 28 for the branch after `2561`/`2562` (V writes to 0x602AE53E). The names are I: 27 = 3d_overlap, 29 = tp_slide, 30 = tp_scroll.
4. **modules.tsv `play_load_raw.c` first_fn 0x7E947893 is not the start of the file.** `play_load_raw_raw_header_check` 0x7E94764F and `play_load_raw_load_prim_raw` 0x7E947719 come before it (V names). As a result they fall inside the `play_load_mpo.c` row.
5. **04 §MJPEG "`00dc` chunk writes 0x7E6F0D88/0x7E6F0C38":** 0x7E6F0C38 is `mov_rec_update` (it updates the video buffer write pointer and reports `video buff FULL!!`). Only 0x7E6F0D88 starts a chunk write (V strings).
6. **rec module rows:** modules.tsv has `rec_misc.c` = 0x7E7166EC only, but 03 §8 puts REC MISC (YC2YC … BAYER2YC 0x7E7154E5) at 0x7E714ABC–0x7E71631A, which is before that row. Also `rec_3d.c` ends at 0x7E70D2F5 in modules.tsv but at 0x7E70D55E in 03 §8.

## Weakest areas

- **The 15c row "Ope API front" 0x7E99A20E–0x7E9CFDFA** (about 220 KB in one row) covers the `sdk api` shell, both OlyApi getter series and every OlyApi method vtable. You can only classify a function there by combining 13d §6.2 (API ids, getters) with 06 §5. The method vtables (e.g. CameraCommon 0x7EBF52BC) and the method roles are not mapped (F035).
- **Bluetooth stack internals** (15d): the layer bounds are good, but almost no functions have a name or role. F028 (L2CAP disconnect) and F026 (BT_CTRL timer) needed tracing from scratch, and the BTTIM row is wrong.
- **OBEX_ACP** 0x7E938594–0x7E93BA6B: only the task entries and three client/server operations are named (F029).
- **User shell 0x7E9630D4–0x7E965FD0:** the map marks it "inferred, not examined", and the regions table row does not mention it (F032).
- **Playback EFFECT:** the bit mapping was open, and the per-bit step functions have no description (F025; partly answered above).
- **Per-function roles inside named classes and modules** (F023 Apical, F034 LowApiWrap, F040 CapImg): the class or module is right, but the map stops at a one-line class role.
