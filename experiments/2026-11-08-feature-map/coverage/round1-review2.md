## Map claims contradicted by the code

None of the 20 functions is CONTRADICTED as a whole. But reading them showed these claims in the map to be false:

1. **Section 05 §5 (SERV_MAIN):** "`SERV_S1` … is called through 0x7E68CCBD from the REC (0x7E701D27) …". **False.** 0x7E701D27 is not REC code:
   - It is inside mcon (0x7E6FC000–0x7E708000, 09a).
   - Its only caller is F021 0x7E7000BA (verified, `calls.tsv`). The other mcon-range caller of the SERV wrapper 0x7E68CCBD is 0x7E701E42.
   - F021 is reached from the mcon shell 0x7E6FDCAE (`modedump`, `modeback`) and from `loadCustom` 0x7EB92769 (`mcon_if_load_custom fail`).
   - Its work is mode-reload housekeeping: `api_rec_Charge_Strobe(0)`, `api_rec_Control_Strobe(0)`, then SERV notice 0x3010007 when 0x7E6FFDF8() == 1.
2. **Regions table, rows 0x7E6A1020–0x7E70B000 and 0x7E70B000–0x7E730000:** the table puts "face detection" in the second row. Section 03 itself places FACE_MAIN 0x7E6F45B8, FACE_FD 0x7E6F82C8, FACE_PT0 0x7E6FC973 and the OKAO wrappers 0x7E6FB750–0x7E6FBF38 in the first row. The first row also leaves out mcon (0x7E6FC000–0x7E708000), which is as large as the movie code. Only the stringless OKAO library (0x7E72CFA1–0x7E732000) is in or near the second row. That library also runs past the 0x7E730000 "mostly data" boundary, to about 0x7E732000.

## Where the map is weakest

- **Blue SDK internals (F026–F031, 6 of 20):** the map gives only approximate ranges. No layer below the Olympus glue is named: HCI link table, L2CAP ERTM-like state machines, RFCOMM/OBEX transport, the BTEVU kick. The stated stack start (~0x7E91D279) is too late: stringless stack code that uses the stack's own shims is already at 0x7E915A00–0x7E9196xx.
- **Third-party libraries without strings:** the OKAO face library (0x7E72CFA1–0x7E732000) has no entry and is partly inside a region labelled "data".
- **mcon (0x7E6FC000–0x7E708000):** 09a and 10a document only the value-list table and two interlock hooks. The 60-byte per-info records have at least 5 callback slots (+4/+8 step, +16 index, +20 list selector, +32 interlock). The per-mode backup (57-entry table 0x7E83EF4C → prm 0x8B64) is not mapped.
- **The C++ app layer between named modules (F036–F040):** modules.tsv names no file between TraShareTakeStatus.cpp and OlyHfwOpeShoot.cpp, and none between OlyHfwPower.cpp and CapDpc_DisplayControl.cpp. But the code holds OlyHfwOpeLevel/PlyCom/PlyMov, the LowApiWrap, PlaySnd, LifeTest and power-source classes. Section 06 calls 0x7E96B000–0x7E9823AB "event constructors", but it also holds Ope-class code (PlyCom 0x7E97B27A–0x7E97C487, PlyMov 0x7E981663–0x7E981F92).
- **Tool gap (not the map):** `fwmap.py` misses functions that are reached only as `mov imm,dN` constants (state-machine handlers stored into RAM). This merges several functions into one, as in F027 (3 functions) and 0x7E93773D (4 functions). It also makes callers/callees look absent ("callers 0, no data words").
