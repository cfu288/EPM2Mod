## 2. Components and protocols

### 2.1 Capability = facade + reactive + interface (V)

Every Cap class follows one pattern (verified on CapBoo, CapFls, CapTak, CapPls, CapImg, CapDpc):
- **getInstance** (58–59 B): `mov (RAM),d0; …; new(N); facade ctor; store; register; return 0x… adjust` — the last call is a 7-byte `add K,a0; retf`, so callers get an **interface sub-object at facade+K**, not the reactive.
- **Facade ctor**: OMReactive base 0x7EBA6375, own vtable, observer lists (0x7EB86DA1), the embedded reactive Cap class (e.g. CapFls at facade+112, CapBoo at +156), member observers, the interface (its ctor stores the interface vtable and clears +4…), then **initRelations** (§3).
- **Interface vtable slots (V on CapBoo 0x7EC3BAE8 and CapFls 0x7EC3C0C0):** 0 = add observer to the *init-OK* list (via 0x7EB88DF1), 2 = add to the *init-error* list (0x7EB88DFF), 4/6 = remove them, 7 = `gen(ev)` to the reactive (0x7EB871B1), 9… = `addObserver` to the class's notification lists (`mov (N,a0),a0; call 0x7EB86DF0`), then the matching `removeObserver` (0x7EB86FB4), then forwarders `mov (4|52,a0),a0; call <method>` to real methods.

### 2.4 Event-forward router, APP_EVENTs and the three extra threads (C2-1, event 11779)

- **Threads (V, thread-name strings; answers 13c open question 3):** `HLS_CALLBACK` 0x7E96CA56, `HLS_EVENT` 0x7E96DB78 (singleton 0x602B0EE4), `HLS_USER` 0x7E9E762F (OlyHfwUserSettingManager). All three are OMThread (0x7EBA708D) active objects.
- **APP_EVENT path (V):** tasks and drivers post `(code, value)` through 0x7E880EFF (118 call sites in 76 functions, e.g. the 3D stub's 0xF00F0000). HLS_EVENT 0x7E96DD58 (`RECV APP_EVENT [%08X][%08X]`) takes each one (receive 0x7E96E380). A pre-filter 0x7E96DB39 runs first; if it returns 1 the event is skipped. Then it offers the event to **Com_EvSenderManager** 0x7EB84345 (code → event class, sent to the registered receiver or buffered; return 1 = consumed). If that does not consume it, 0x7E96DE42 forwards it to EVFW subscribers (`EVFW TO`). An unmatched code is kept in a backup list (0x7E96DFFC, `NOT FOUND EVFW BACKUP`) only if its top nibble is 0xF (test 0x7E96DE2F); any other unmatched code is only logged (`NOT FOUND EVFW`). A separate replay function 0x7E96DF97 (← 0x7E96DAA3) prints `EVFW FROM BACKUP` (A6 2026-11-09).
- **EVFW router (V):** singleton 0x602B1FE8 (getInstance 0x7E974D11, 482 callers; ctor 0x7E999809, two collections at +4/+20), delivery method 0x7E999883. It handles **11775** register forward (`evHfwReqRegisterEvent`: register for one APP_EVENT / request handle; name from DevRec 0x7EB92CEB, which logs `evHfwReqRegisterEvent(APPEVENT_STATE_STEP)` and builds 11775 with ctor 0x7E96B3AB; 15c §3.1) (D3 2026-11-09), **11776/11777** subscribe (code / range: find or create a 44-byte topic 0x7E9E5384 and add the observer), **11779/11780** unsubscribe (remove the observer; drop the topic when empty), **2201** run an API callback on HLS_CALLBACK, **2205/2206** add/remove a listener (+20), **11794/11795/11800/11801/11802/11803** subscribe/unsubscribe at HLS_USER (all settings, or setting group 0..21), ~~**11805** a record in the HLS_EVENT trace ring.~~ **11805** a **blocking wait for an event code** (timeout +40, result to *(+32), −1 = no event): the handler writes a trace record first (0x7E96CF2E + 0x7E96CFF3, as the 11775 handler 0x7E999D7B also does), then builds an on-stack waiter (0x7E9E8914, vt 0x7EC1C1F4) and calls 0x7E9E89BA(code +28, +36, timeout +40), which registers it with HLS_EVENT (0x7E96DAA3, priority 50), waits on its semaphore (0x7E96D9EA) and unregisters it (0x7E96DC37). CapTak slot 72 (End; thunk 0x7EA3794F → 0x7EA33DC7) posts 11805 with timeout −1 when its second argument is 1 to wait for the end-of-take event of its handle (A7 2026-11-09). Errors return 0xF0000016.
- **Correction to review F036:** event 11779 is **unsubscribe**, not publish. CapGSld 0x7EA56A6B unsubscribes its observers +1180/+1156/+1204 from topics **0x04170003/0x04170002/0x04170001**; `gpu_slide_play` 0x7EA56935 subscribes (11776, ctor 0x7E96B3E4) to 0x04170003 with +1180 (V).
- **Codes 0x0417000x (I, strong):** APP_EVENT codes of the C3D slideshow. The overlay C3D scene code also posts 0x04170001–4 (0x7F09E12F, 0x7F09E19E, 0x7F09E7E7 next to `P3D_Photo_*` strings, 0x7F0A2805) through 0x7F09E235 (`{11, code, arg}` message).
