## 4. Version-check reconciliation (10f §4.3 against 13d §4.3), from the code

1. **GUI event 0x9628 `EVT_REQ_START_VERSION_CHECK`.** Block 0 has the u32 0x00009628 in five places: the GUI self-post immediate at 0x7EDFD68F (instruction 0x7EDFD68D, in 0x7EDFD665, after the getShippingInfo(4) gate), the sendEvent table entry 0x7EEF37E0, the evmap rows 0x7EFC3D24 (SS1) and 0x7EFD3874 (SS3), and the name table 0x7EFDF298. `functions.txt` has only one `mov 38440` (0x7EDFD68D). The descriptor decode shows that only SS3 state 4 `ID_ST_WIZARD_MENU_ENTRY` has a real handler: idx 36 → 0x7EDAB90A = `mov 6,d0; retf` → `ID_ST_HIDE_MODE`. The SS1 row has only default handlers.
2. **The CA → GUI route also exists.** GuiCallerImp::sendEvent 0x7ECE6E27 checks code 1..167 and reads the GUI event at 0x7EEF3434 + 8·code + 4. Code 0x75 → 0x9628. No `mov 117,…` exists in 0x7ECC0000–0x7ECEFFFF, so no CA sender was found.
3. **The Firmware item path.** 0x7EDA9D03 is handler idx 13 of SS3, used only for event 0x900C in state 4 (descriptor decode). Its strings include `doCmd_SsMenuMain_StWizardMenu_EvtKeyOKOn`. At 0x7EDAA626 it does `cmp 43` → `mov 11,d0; mov 12,d1; call 0x7EDC5C47`, then logs `F/W Version up start`.
4. **PostEventToCA 0x7EDC5C47** stores {d0 code, d1 param} at (16,sp)/(20,sp) and calls slot +4 of the object from 0x7ECE39D2 (vtable 0x7EEEC80C, slot 1 = 0x7ECE3A9E). 0x7ECE3A9E looks up the code in the 22-entry table 0x7EEEBB28: code 0xB → 0x0400000B. Name table 0x7EEEFC88: 0x0400000B = `GUI_START_SHOOTING_SERVICE`. The param stays in the second word.
5. **startShooting 0x7ECDCB10** (CA rows with events 0x0300000B / 0x0900001F / 0x01000002) reads info = second word. It maps 11 → 0x7ECD6574(12 = VERCHK) and 12 → (13 = FIRMUP). The 0x0400000B handlers are 0x7ECDCF0D (→ 0x7ECD27A7) and 0x7ECE214F. I did not trace how 0x0400000B reaches startShooting, so "item 43 → FIRMUP" is inferred for that one step. The log text `F/W Version up start` supports it.
6. **No constant PostEventToCA(11, 11) exists.** All `call 0x7EDC5C47` sites with `mov 11,d0` pass d1 = 3, 8 or 12, or a setting value (0x7EDAD0D3). So nothing found starts VERCHK.

**Result.** 10f and 13d no longer disagree. 0x9628 is the GUI-side debug-menu entry event, which leads to HIDE_MODE. The Firmware item is the firmware-update path (CAM_MISC_FIRMUP). The CA "version-check menu" (CAM_MISC_VERCHK_MENU) has no trigger that I found; by its name it probably pairs with 0x9628 (inferred).
