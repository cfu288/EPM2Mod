## Non-CORRECT claims

**15b-93 (MINOR).** The completion and list-done families check out. The frame-done family does not hold "21 × 27 B". The range has 18 functions: 16 frame-done stubs of 27 B, 0x7E65179E (11 B, `call 0x7E652171; ret`, a list-release stub used by COM_SET) and 0x7E6517FA (36 B, free + forward to the owner's done at +20, used by the code-100 handler). The 2/4/8 operands go to 0x7E63589A, which ORs them into the object's flag word (0x7E635C75). So they are masks, not bit numbers.

**15b-216 (MINOR).** The row reduces the start step to "send 7". In the code, 0x7E52FE8C first reads the two protocol flags. Type 1 (1,0) sends 7. Type 2 (0,1) sends 0x1007. Both set (1,1) reports 0x6610 at once, with no retry. Neither set (0,0) sends a probe through 0x7E53048E. That probe's done 0x7E5304BA restarts the chain when a flag appears; else it increments 0x604F939A and reports 0x6610 when the count is > 3. The fw_kind helper also returns byte − 79 for other letters.

**15b-169 (WRONG).** The pattern is asserted for all eight addresses, and three of them break it. 0x7E67287A has no `movm` and no result decoder, and it ends in an indirect user callback. 0x7E671E92 calls 0x7E672308, which is not a start. 0x7E6725C6 ends with an indirect `calls` and has no direct start call. These three are the chain ends (final callbacks). They are not links to a next start.

**15b-244 (WRONG).** The "no user found" list is mostly false. The ADC key uses 22, MEC 0x7E51773D uses 39 through the static request 0x7E45BADC, and the ccd_temp module (0x7E45E206 → 0x7E45E556 → 0x7E45E411) uses 41. Only 21 still has no user. Also, channel 34 is shared by per_acc and ccd_temp, and only one ADC-key function (0x7E50B356) sets callback 0x7E50B724.

**15c-57 (MINOR).** The final step "calls CM unsubscribe 0x7EA7DB1E" names a function that is an empty `retf`. The subscription list also leaves out +704's 11776 subscription to 0x04020011, which 0x7EB0B054 makes. That code is the one §8 Q1 asks about. All the other registrations, codes, offsets and slot numbers match the code.

**15c-140 (WRONG).** The F042 sentence names the wrong composite. +1300 is the sub-state word of composite 33. Sub-states 34 (0x7EAF2F90) and 35 (0x7EAF2FE7) both write it, so 35 is a sibling of 34, not inside it. The CustomPrint mapping from idle (13) also leaves out at least eight requests that do enter states (13796, 13798, 13801, 13810, 13813, 13815, 13789, 13820). The sub-state word range is +1300…+1376 plus +540, not +1300…+1364. The dispatcher, case count, idle entry, the listed mappings and the 7094 self-GEN are right.
