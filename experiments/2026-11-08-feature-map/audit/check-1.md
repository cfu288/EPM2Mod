## Notes on non-CORRECT claims

**01-11 (MINOR).** The S_SHELL loop at 0x7E44E972 treats a line that is just `:` as a toggle (`a2 = 1 - a2`). When the toggle turns on, it sends "\n" (0x7E47411E) to the message buffer whose ID is at 0x7E43EE3C. U_SHELL (0x7E503CD0 → 0x7E44EA5C) reads that same message buffer. While pass-through is on, a plain line goes to that buffer and a `:cmd` line runs locally. While it is off, every line runs locally, including `:cmd`. So `:` does not mean "send this line on". It switches forwarding on and off.

**01-31 (MINOR).** The values are right, but "0x8085…0x80E0" suggests a contiguous run. Entries 9–16 are 0x8058, 0x80AE, 0x8001, 0x8007, 0x80C0–0x80C3, and the run 0x80D9–0x80E0 follows them.

**01-104 (MINOR).** The log dump runs only for `usr fast log`, which needs three arguments.

**01-186 (MINOR).** The buffer address is wrong by 0x2100. The immediate at 0x7F05DF86 decodes to 0xBC61DF00, and the same register is then stored as `src_addr` (+16 of the request) for flash_mem.

**01-196 (MINOR).** The behaviour is correct, but two identifiers are wrong. The raw task record gives ID 0x2E for entry 0x7E45DBB5, which matches `fwmap.py tasks`. The table immediate is 0x7E4C4DF8: 12 bytes of state/event data, followed directly by the CCD shell strings "help", "int-start", ….

**02-162 (MINOR).** LENS_FOCUS_LIMIT is a queue consumer that does not reply, so "all … → reply" is false for that one task. The ZOOM "event bit 2" is really mask 0x02 (bit 1). Note also that LENS_MAIN and ZOOM reply only when the message carries a reply queue (`cmp 0` on (32,sp) or (40,sp)).

**02-171 (MINOR).** `src` is shorthand for the two commands `get_src` and `set_src`. The help string is "1=AC, 2=BAT".
