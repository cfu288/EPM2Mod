## Non-CORRECT claims

**15c-121 (MINOR).** The state number, the GEN of 11565 to self, and the inline 11565 → 3 branch in the dispatcher are confirmed. But the entry action column is incomplete. After the GEN, entry 0x7EB785F8 also calls 0x7EB783AF. That function calls virtual methods on seven relations (+352 CapThr, +344 CapPow, +348 CapTak, +336 CapMed, +332 CapIod, +324 CapBlc, +340 CapMod). It mirrors 0x7EB782C1, which the 11761 path runs (the state-2 entry 0x7EB7864A). So state 1 is also where the Shutdown component unsubscribes its observers (I). The row should read "GEN 11565 to self; 0x7EB783AF (relation unsubscribe, I)".

**15c-166 (WRONG).** The slot-42 column holds for all 8 classes: six use the base `retf` 0x7EB85924, and Outline and Bufferd have their own `retf` stubs. But the "none" in the accepted-ids column is false for `Com_ActiveTransitionManagerBufferd`. That class does not use slot 42. Instead, its state-4 regions (states 7 and 8) push the static 13361 prototype (0x605EF18C) onto +144 when they are entered, and remove it when they exit. 0x7EB857CA checks +168 == 4 and then this list, so Bufferd accepts **13361** while it runs. Cab_CameraBase 0x7EB896CA queries it through +276, which initRelations 0x7EB893EA points at the Bufferd member at facade+128. The §4.8 rule "the slot-42 override fills the array" therefore has an exception. The Bufferd entry should read "stub slot 42; +144 = {13361} while in state 4, filled by entries 0x7EB8B66F/0x7EB8B8EA". Also, the address after "Outline" is the slot-42 stub 0x7EA7E6EB. The ctor is 0x7EA7E66B. The other entries in the list are ctors.
