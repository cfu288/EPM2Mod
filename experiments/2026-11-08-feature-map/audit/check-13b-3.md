## Non-CORRECT claims

**13e-132 (MINOR).** The claim line itself is accurate. The state table has 27 entries with the stated 20-byte layout and matching names. Every send that the table names was found at a matching site, with the corrected command names. The table it introduces has three transition errors. First, the Standby row merges two different handlers into "A7/A9 → RdyAbort". The handler 0x7E5A190C tests the event: event 9 sends EXP 0x601 + FCS 0x501 (`release_take_end`), replies, and sets state 6 (RdyTrig2Wait); event 7 sends EXP 0x701 + FCS 0xE01 (`release_end`) and sets state 10 (RdyAbort). Second, "A7/A2 → RdyAbort" holds for RdyTrig2Wait but not for RdyFastTrig2Wait. There A2 is the no-op handler 0x7E5AADBC, which returns 0xFFFF. Third, Damage does not reject all A events: six of its 14 A entries use the ignore handler 0x7E582546.

**13f-81 (MINOR).** The register set, the bit-0x10 toggling, and the user functions and their callers are all correct. The one wrong detail is the offset base for the twin function. 0x7E95F008 accesses 0x98100444/0x98100448, which is +0x44/+0x48 of the 0x98100400 unit. It mirrors 0x7E95EFC8's +0x44/+0x48 on the 0x98100000 unit. "+0x444/+0x448 of the 0x98100400 unit" would mean 0x98100844/0x98100848, which nothing accesses.

**13f-97 (MINOR).** The 197-register count, the IRQs, the ISRs and the init are correct, but two details are wrong. The access count is wrong: the code has 328 instruction operands in the block, in 74 functions, not 92. The SH_RES/SH_MEM objects do not follow the register code. Their users (0x7E6557CE–0x7E655D4B) lie inside the cited range 0x7E653AB1–0x7E65663A, and more register users come after them. A small extra precision: IRQ 7's ISR 0x7E65628B is registered by 0x7E6561DA, not by the init 0x7E653AB1. The row does not claim otherwise.
