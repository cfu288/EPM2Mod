## Notes on non-CORRECT claims

**13c-12 (MINOR).** The row's own basis ("string tags") disagrees with its lower bound. The file tag `TraShareTakeStatus.cpp` is used by 0x7E969F7B, 0x7E96A14E, 0x7E96A422, 0x7E96A52A and 0x7E96AF2A, all below 0x7E96B000. Only 0x7E96B048 is inside the row. So the `Tra*` package starts at about 0x7E96998B, and the previous row ("HIGHLEVEL_MAIN entry, HLS OS wrapper, growable array, logger") ends there, not at 0x7E96B000. The contents listed for the row are present.

**13d-14 (MINOR).** "Verified bytes" missed what the bytes are. The 108 KB "block" is 0xFF erased fill (only the first 3 bytes `de 00 00` are not 0xFF), so it is padding, not a data table. It runs to 0x7ECCB800. That also moves the next row's start from ~0x7ECC8000 to 0x7ECCB800, which fits its first cited address 0x7ECCBA45. The ramp tables and the false 15 KB "function" 0x7ECAD443 are correct.

**13d-17 (MINOR).** Every named function is correct. The 0x7ECEC000 start is a round number that cuts function 0x7ECEBE26. The 0x7ECEBE26/0x7ECEC1E8 pair is GPI-layer code (callees 0x7ECEA7ED…0x7ECEAD0A). The pool module starts at 0x7ECEC799.

**13d-66 (MINOR).** The addresses and the slot +244/+248 accessors are exact. "Selected by the bytes at object +28/+29" is true only for the root-object family. Most of the 205 call sites pass constant pool ids or the +17/+18 bytes of another object type.

**13d-121 (WRONG).** The main assertion is a closed call graph, and it does not hold. One rotation routine, 0x7ED3231E, calls 11 soft-double math routines in 0x7E4FE2xx–0x7E501Axx (sin/cos-style range reduction with π and 2π constants, fabs, conversions). These calls are outside the toolkit and are not memcpy, memset or UTF-16 helpers. The stated ranges also start and end inside functions, and the resource-lookup helpers listed under the bullet are outside them.

**13d-135 (MINOR).** The layout is verified except one constant: field +20 is 0xFFFE or 0xFFFF. Each record's two rects are the same in all 114 records. This does not falsify the inferred "two outputs" reading, but nothing in the data supports it.

**13d-156 (MINOR).** The signature is the majority form (93/115) but is written as if it were universal. It also leaves out the `mov a0,a2` that always follows the base-ctor call when (a2) is used. A minority of ctors use (a0), zero from +796, or have no tail calls.

**13d-218 (MINOR).** The menu-item facts are correct: vtable 0x7F00095C, slot 0x7EDF26B2, string 1782, ShowPanelEx(111). The "callback" is a virtual method of a second, separately constructed class (vtable 0x7F0010B4, factory 0x7EDF2A25 / id 0x20D). The code does not show the item reaching it, so that relationship and "userMenu item" are inferred, not verified.
