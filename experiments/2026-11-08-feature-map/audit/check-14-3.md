## Non-CORRECT claims

**14e-50 (MINOR).** The slot mapping and masks are right: 64/65 set and test 0x2000, and 66/67 set and test 0x1000, through setStatusBits/testStatus (vt+116/+120). But slot 68 (+272, 0x7ECEF036) does more than clear both bits. After vt+264(0) and vt+256(0), it does `clr d0; mov d0,(40,a2)`, which zeroes the +40 plane-mask dword (slots 75–78). This is relevant to the open "role" of 0x1000/0x2000 in §2.6: +272 is a reset of both flags and the plane mask.

**14e-88 (MINOR, five details).** The role and every bold assertion are confirmed: the images +160/+164/+168 and the picker logic, the 0x1000000 password mask at 0x7ED2E070, the 0x10000 numeric rebuild through 0x7ED2F453 and the digits at 0x7EF146DC, slot 163 as the 0x10000 setter, the size of 204, and the 195 slots. But five details in the row are wrong. The instruction counts are 446 (DrawSelf) and 508 (key press), not 324 and 468. +184 and +190 are byte fields. +136 is a 24-byte block. The caption text is the UTF-16 buffer at +192; +172 is its maximum length (default 32), and +200 holds the current length. Slot 188 returns both values. The fields column should read: "u16 +128/+130/+186/+188, bytes +184/+190, 24-byte +136, dwords +176/+180, caption buffer +192 (max length +172, length +200; slot 188 returns both), second buffer +196".

**14e-102 (MINOR).** The main assertion is confirmed: each C-part OnDraw calls exactly one renderer, at the stated addresses. The parenthetical for C004 is wrong. 0x7ED35160 receives a0 = DC and a1 = part+88. It tests the u16 at **DC+64** with `btst 1` (mask 0x1, bit 0). It does not test part+64. Also, the "(slanted fill)" role for C003 comes from 0x7ED34FE9 calling 0x7ED31C9B, which line 229 labels I. Here it has no I label.
