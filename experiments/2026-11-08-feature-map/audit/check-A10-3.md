## Notes on the non-CORRECT claims

**15b-60 (WRONG).** The table cell makes two assertions. The code list 5, 6, 7, 11, 12, 145–149 is right: the filter subtracts 4 before the hash lookup, and the 0x7E7BBAAC keys decode to exactly those codes. The claim that "each" code goes to the MEC submit or the cam timer is false. Code 145's handler 0x7E655A2E is a two-instruction no-op (`clr d0; retf`). Code 148's handler 0x7E655A5E only writes 1 to byte +1 of the shutter state *(0x6056EB44), and code 11 clears that byte. Neither one submits or arms a timer. Also, "or" is not exclusive: codes 7 and 11 arm the cam timer twice and then submit.

**15b-94 (MINOR).** The 13 listed values are the complete set of FrameTypes given to 0x7E65156C. But the same executor 0x7E6513CF is also reached from COM_SET through 0x7E651520, which skips the builder and runs the packet's own list. That path uses types 61, 64 and the caller's pkt+4 value. A complete list is therefore 10, 16, 34–37, 54, 57–59, 61–65 (and caller-supplied values), and 13 of the 15 fixed values are default slots of 0x7E7AE744. The conclusion is unchanged. (The COM_SET row at 15b line 69, "types 57, 58, 59, 62, 63", omits 61 and 64 for the same reason. That row was not sampled.)

**15b-169 (MINOR).** The structure is verified: 5 relay callbacks and 3 chain ends, which are all 8 zero-caller functions in the job layer, together with their loaders, next-start calls, the user-callback slots and the tracking-open arguments. Two details are wrong. First, 0x7E46118C is listed among the decoders of the five relay callbacks, but none of them calls it; only 0x7E671E92 does. Second, both chain ends run 0x7E672896 only under a flag (byte 0x605970E4 != 0, and in 0x7E672308 also a once-flag 0x60598D0C), but the text says they always run it.

**15c-94 (MINOR).** The listed transition 3 → 9 on 11761 is correct. The row does not show that the state-3 handler also consumes 11769 (it calls 0x7EA7D5F0 on this+188) and 11770 (it calls vt+20), with no state change. This is the "incomplete map" error class: the Shutdown chart in the same section lists those two events for its state 3.

**15c-141 (MINOR).** The 23 ⇄ 24 pair, the entry GEN of 3615 and +1256 = CapPbr are all verified. The text omits the 23 → 24 trigger 7093, and the quoted log string belongs to the 7093 branch. The 7079 branch logs `CmpPbr0 err %d` instead. Read as written, the text implies that 7079 is the abort-success event.

**15c-170 (MINOR).** The pushes, the prototype, the slot-42 stub, the state-4 gate and the Cab wiring are all verified. The removal text names a single exit, 0x7EB8B458. That exit only removes the prototype when region +316 is in state 7. The state-8 copy is removed by 0x7EB8B86A, the exit of state 8's sub-region (+324). The state-7 handler 0x7EB8B69E also removes the prototype itself on 7014 and on 13361.
