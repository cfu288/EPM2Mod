## Notes on non-CORRECT claims

**05-13 (MINOR).** The task loop, the subscriber-list broadcast and the register/unregister control path all hold. The range starts 0x1E bytes late: the module's init function, 0x7E8F9031, clears the same subscriber table (0x605C22F8 ×8 and the count byte 0x605C2318). It is part of SERV_MAIN and is called from the task-creation code (0x7E504AF9).

**05-17 (MINOR).** The identification evidence holds: the four task entries are inside the range, the "OLYMPUS BlueSDK a4" string exists, and there are RFCOMM SABM/MUX strings. Both bounds are round numbers that cut functions in half. The start includes the tail of the Olympus iAP function 0x7E91CD59. The end includes Olympus `obex_acpl_*` glue (0x7E937CDE–0x7E937FFF). The range also contains Olympus test/console code such as "please input bt pin", BT_CliCallback and OLYMPUS_TST_OBJ (around 0x7E923769–0x7E923F32), so it is not pure SDK code.

**05-158 (MINOR).** The debug hook reads setting 10442 [0..2], sleeps, and then plays HOGE.WAV (action 2) or records at 48 kHz (action 3). There is no volume-change action. The "volume level change" log only fires when work_info (the play volume) is above 10; the code then clamps it to 10.

**05-228 (MINOR).** The HCI bytes, the Write_RAM/Launch_RAM opcodes, the TX buffer and the send function are all correct. bt_config_set calls 28 command functions: the 27 Write_RAM chunks in the stated range, which load 0x87558–0x88F40, plus the separate Launch_RAM at 0x7E912680. So "27 functions … the last (0x7E912680)" contradicts itself; the total is 28.

**06-92 (MINOR).** On MN103, `btst imm,Dn` ANDs a mask; it does not take a bit number. 0x7E969C5B is `f8 ec 0e`, which tests mask 0x0E (bits 1–3) of the interval state, not bit 14. The guard also has a "RecView or Recording" check (0x7E969A6A) that the claim does not mention. All addresses, the mode-482 read, getTakeFuncState(18/9), the event ID 12047, the vtable and the constructor are correct.
