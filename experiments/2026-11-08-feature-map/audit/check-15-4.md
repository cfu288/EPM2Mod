## Non-CORRECT claims

**15d-199 (MINOR).** The function 0x7F061CED is a range/step validator that returns 0 or −198, as the claim says. The count is wrong. fwmap's `callers` count column counts call sites. The xref shows 13 `call 0x7F061CED` sites in 6 functions: 0x7F061F89 ×2, 0x7F062111 ×1, 0x7F0621AD ×2, 0x7F062302 ×2, 0x7F06287E ×1, 0x7F06289F ×5. The correct text is "13 call sites in 6 callers".

**15d-286 (MINOR).** The main correction is correct: Blue SDK part 1, including the HCI layer, sits inside 05's "0x7E913984–0x7E91CFFF" row, and L2CAP starts at 0x7E91D29F. Two details are wrong:
- The upper bound 0x7E91962B includes 0x7E9195A7. That function is iAP setup: its only caller is `cp_init()`, it uses Olympus RAM 0x602AEDxx and kernel wait/signal calls, and it registers the iAP callbacks 0x7E9196D9/0x7E919CEB with SPP. So the stack ends at 0x7E9195A6 and iAP starts at 0x7E9195A7. The same bound is also in §1 and §2.1 of 15d.
- The claim calls both 0x7E91D279 and 0x7E91D289 "iAP getters". Only 0x7E91D279 is a getter. 0x7E91D289 (called from the demo shell 0x7E9035A8) sets the field 0x605C6028 = 19 and calls the iAP dispatcher 0x7E91C673, which switches on context +906. It is an action, not a getter.
