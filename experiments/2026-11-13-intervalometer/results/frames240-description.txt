Interval shooting: Frame (info 483) up to 240 instead of 99, for use on top of the film set + interval-timelapse-v2.json (it also applies on stock). Choices: 1-99 by 1 as before, then 100-240 by 5 (128 choices; the list editor cannot index more than 128 rows, and the count is stored in one byte). Data only, no code, no block-1 change. (1) mcon value list: a new 128-byte list at 0x7E4C9100, in the 0xFF padding the reset stub loads with the kernel range (0x7E430000-0x7E4C9800); record 0x7E84C5FC points to it with total 128 (the old 99-byte list stays). (2) Frame editor (list 638): 128 items of 28 B at 0x7EBF1100, inside the unreferenced `sdk` shell name list 0x7EBF1090-0x7EBF3BAC (segment 2; experiments/2026-11-13-reclaim-space); descriptor 0x7F00C6EC gets count 128 and the new pointer. Items up to 99 keep the stock label strings ("1f".."99f", kind 2); 100-240 use the composed form of the Custom Self-timer editor (kind 4 = number + unit string) with unit string 0 (empty), so they read "100".."240". (3) Sub-item value rows (table 0x7EFF0460): the row of value 99 becomes kind 4, so the Time Lapse Settings list shows 99 and every value from 100 as a plain number (1-98 keep "Nf"). Side effect: the `sdk` debug-shell name list loses 3.6 KB of its text (UART / factory shell only). NOT BUILT, NOT CAMERA-TESTED: the plain-number label, the on-screen counter above 99 and a time-lapse movie from more than 99 frames are untested. Restore = the previous build.
